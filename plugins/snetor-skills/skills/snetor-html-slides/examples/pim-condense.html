Enjeu · pourquoi un PIM

Du bricolage manuel à un référentiel produit gouverné

Aujourd'hui : circuits fragiles entre SAP, SharePoint, GLPI et fichiers locaux. Demain : un flux propre, du besoin métier jusqu'à SAP.

Créer

Création produit assistée.

Documenter

Dernier document valide.

Valider

MDM, rôles, audit trail.

Publier

Écriture SAP tracée.

Sans data produit structurée, pas d'IA. Le PIM est la fondation.
Baseline vérifiée : 42 038 documents retenus, 776 870 lignes sap.article. Scope V1 borné (EP toutes entités, PE SNFR, PP SNFR) — pas une migration de 57k docs en bloc.
Source : 02-Wiki/pim/2026-06-22 - Note de décision PIM Snetor.md (§1, §2)
Finalistes · deux voies

Deux approches en tête, au coude-à-coude

Acheter — Akeneo · score 87

Importer la maturité : couverture native, pérennisation, support éditeur.

Construire — full custom · score 86

Internaliser la compétence : adoption, fondation data, autonomie.

Le score ne tranche pas (86 vs 87). Le choix est stratégique, pas arithmétique.
Profils miroir → scores très proches. SpecialChem challenger (~78 provisoire) hors finalistes tant que workflow, extraction IA et TCO ne sont pas prouvés. Twenty, Pimcore, NeoLedge derrière.
Source : note de décision PIM §6 (grille pondérée)

Akeneo 613,25 k€ : éditeur 270 (souscription 204 + intégration SaaS 42 + intégration CRM 24), interne recruté 227,25 (dev/DevOps 146,25 + data steward 81), socle 116 (infra/IA 36 + contingence 80). Home-made 549,5 k€ : éditeur 24 (intégration CRM), interne recruté 373,5 (dev/DevOps 292,5 + data steward 81), socle 152 (infra/IA 72 + contingence 80). Chiffres au k€ près = deck complet slide 9.

Périmètre · un seul programme

Un budget, deux livrables

PIM produit

Le référentiel produit gouverné : créer, documenter, valider, publier vers SAP.

CRM interne — Twenty

La relation client internalisée, open-source, sur la même fondation data.

Une équipe recrutée, une infra, un budget. Le CRM roule sur l'investissement PIM : + 24 k€ d'intégration, pas un second budget.
Le run (équipe recrutée + infra) est identique entre PIM isolé et programme PIM+CRM. Seul écart = 24 k€ d'intégration CRM en build. La capacité est mutualisée sur les deux projets.
Source : note de décision PIM §8 · deck complet slides 6 & 9
Décision COMEX
Notre choix : construire. Le PIM home-made, full custom.

Score quasi égal (86 vs 87), coût plus bas (549 k€). Surtout : on internalise la compétence au lieu de dépendre d'un éditeur — au regard de nos expériences passées avec les éditeurs.

Autonomie Adoption Maîtrise de la data Coût maîtrisé
Prochaine étape : benchmark final sur dataset Snetor, puis build de 4 mois.
Décision assumée : full custom. Choix stratégique d'internalisation face aux expériences passées avec les éditeurs. Build 4 mois puis run ; 1,4 ETP recrutés. Akeneo reste le plan B crédible si la capacité interne se sature.
